1. PROJECT OVERVIEW
This project is a GameMaker Studio 2 pixel-art dungeon RPG with low internal resolution and integer-scaled presentation.

Confirmed systems in current code:
- Overworld exploration with tile-based movement and room transitions.
- Turn-based 1v1 battles in `rm_battle`.
- Player class system with `Knight`, `Archer`, `Mage`, and `Nobody`.
- Dialogue/typewriter UI and cutscene flow in `rm_cutscene`.
- Inventory, equipment, consumables, skillbooks, loot tables.
- Save/load slots with room position restore.
- Global transition manager (room fade, encounter zoom/fade, cutscene fade).
- Difficulty selection and runtime difficulty multipliers.

Intended (by naming/comments/flow):
- Data-driven systems (`DB` scripts, room DB, status DB, loot DB).
- Reusable centralized managers (game state, UI, transitions, audio).

Actual:
- Most systems are centralized and data-driven.
- Some legacy/stale artifacts and behavioral mismatches exist (see sections 16 and 17).


2. CORE GAME LOOP
Overworld:
- Player moves on a 16x16 grid (`obj_player/Step_0.gml`), 1 px/step until tile settle.
- Interactions are tile-facing checks through `obj_interactable` + `Interact_Handle`.
- Enemies use chase/wander AI (`EnemyAI_Update`) and collide with player to trigger battle.

Room transitions:
- `obj_room_transition` collision reads `transition_id` and `RoomDB_Get`.
- Direction/intent gating: `require_dir` + `require_move`.
- If entry has `cutscene_id`, transition routes to cutscene flow.
- Otherwise room fade transition + spawn routing.

Battle entry:
- Enemy collision path:
  - Guards: defeated/transition active/player cooldown.
  - `EnemyPersist_BeginEncounter` captures return room/x/y and enemy identity.
  - `Transition_RequestEncounterBattle(rm_battle)`.
  - Enemy and player movement frozen immediately.
  - Enemy encounter SFX plays once on trigger path.

Battle exit:
- Win:
  - Rewards applied (EXP + loot roll).
  - Enemy persist marked removed (boss flag update if boss).
  - Returns to overworld via room fade.
- Run:
  - Enemy marked alive in persist.
  - Returns via room fade.
- Death:
  - Triggers cutscene transition with cutscene id `game_over`.

New game flow:
- `rm_start` main menu -> difficulty popup -> intro cutscene transition.
- `rm_cutscene` plays `intro` sequence.
- On intro completion:
  - state reset
  - class forced to `Nobody`
  - transitions to `rm_floor1`
  - immediate floor1 intro dialogue is queued and shown.

Class selection flow:
- No dedicated class room.
- In `rm_floor1`, interacting with `obj_chest_class_select`:
  - shows class prompt dialogue
  - opens class selection popup
  - on selection, class apply + black flash transition.

Ending flow:
- Room transition id `floor9_5_to_ending` routes to `rm_cutscene` with `ending` cutscene id.
- Ending sequence plays multi-segment cutscene and returns to `rm_start`.

Save/load flow:
- Save menu opened from bed (`obj_bed` checkpoint interaction) or main menu load.
- Save writes snapshot, resets regular enemies, then save flow reloads selected slot.
- Load restores player class/data, exact room position, and triggers cutscene-style fade transition into saved room.

Death/game over flow:
- `Player_OnDeath` or debug kill transitions to `game_over` cutscene.
- On cutscene completion: load current/latest save slot if available, else return to main menu.


3. PLAYER PROGRESSION
EXP progression:
- `Exp_NextLevel(level) = 10 + level^2 * 10`.
- `LevelUp_FromExp` loops while `exp >= exp_next`.

What level-up is intended to do:
- Intended by function naming/known design: class auto-growth + manual stat point gain.

What level-up actually does:
- `LevelUp_AddStat(_ch, _stat_id)` increments:
  - `level += 1`
  - `stat_points += 1`
  - recompute resources
- `_stat_id` is currently unused.
- Result: no automatic class-stat increment is currently applied.

Manual stat allocation:
- Stats tab in menu allows spending pending stat points on STR/AGI/DEF/INT/LUCK.
- Confirm/Cancel apply or discard pending allocation.

Level cap:
- No explicit level cap enforcement found in level-up logic.
- `STAT_MAX` macro exists but is not applied by level-up/menu allocation path.
- Technical implication: level can continue as long as EXP is added.

4. CLASS SYSTEM

- `CLASS_ARCHER=0`, `CLASS_KNIGHT=1`, `CLASS_MAGE=2`, `CLASS_NOBODY=3`.

Class DB (`DB_PlayerClass`):
- Knight: `hd=10`, `mp_gain=1`, `base_hp=10`, `base_mp=10`, bonus `{str+1, def+2}`.
- Archer: `hd=8`, `mp_gain=2`, `base_hp=10`, `base_mp=10`, bonus `{agi+2, luck+1}`.
- Mage: `hd=6`, `mp_gain=3`, `base_hp=10`, `base_mp=10`, bonus `{int+2, luck+1}`.
- Nobody: `hd=8`, `mp_gain=1`, `base_hp=10`, `base_mp=10`, bonus all zero.

Sprite assignment:
- `Player_ApplyClassSprites` maps class to directional sprites.
- Nobody uses `nobody_right/left/up/down`.

Class selection:
- Popup choices are labeled `Warrior`, `Archer`, `Mage`, mapped to class IDs `[Knight, Archer, Mage]`.
- Applying class rebuilds character, preserving selected old fields (level/exp/inventory/equip/stat_points/status).

Nobody behavior:
- Starts with no skills.
- Skillbook validation explicitly blocks Nobody from learning skills.
- Skill use checks class restrictions, so player cannot use out-of-class skills.
- Nobody can still use basic attack and items like any class.


5. PLAYER STATS / FORMULAS
Base stat creation:
- `StatsCreateBase`: all 10.
- Class bonus added at character creation.

Stat modifier:
- `StatMod(stat) = floor((stat - 10) / 2)`.

Combat stat retrieval:
- `Stat_Get(ch, stat_id) = base stat + equip bonus + status mod`.

Resource recompute (`RecomputeResources`):
- Uses `ch.stats` directly (base allocated stats), not `Stat_Get`.
- `hp_gain = ceil(hd/2) + 1`.
- `max_hp = base_hp + (level - 1) * (hp_gain + StatMod(stats.def))`.
- `max_mp = base_mp + (level - 1) * (mp_gain + StatMod(stats.intt))`.
- Player then applies difficulty multipliers:
  - `max_hp *= diff.player_hp_mult`
  - `max_mp *= diff.player_mp_mult`

Starting class stats at level 1 (confirmed):
- Knight: STR 11, AGI 10, DEF 12, INT 10, LUCK 10
- Archer: STR 10, AGI 12, DEF 10, INT 10, LUCK 11
- Mage: STR 10, AGI 10, DEF 10, INT 12, LUCK 11
- Nobody: STR 10, AGI 10, DEF 10, INT 10, LUCK 10

Default no-manual-allocation per-level HP/MP increments on Normal:
- Knight: HP +7, MP +1
- Archer: HP +5, MP +2
- Mage: HP +4, MP +4
- Nobody: HP +5, MP +1

Important actual behavior:
- DEF/INT allocation retroactively scales full HP/MP formula (because formula multiplies by `level-1` each recompute).
- Equipment/status bonuses do not change max HP/MP (resource recompute does not use `Stat_Get`).


6. COMBAT FORMULAS
Initiative:
- `RollD20() + StatMod(Combat_EffectiveStat(ch, AGI))`.

Effective combat stat:
- `Combat_EffectiveStat = round(Stat_Get * difficulty_stat_mult_for_side)`, min 1.

Attack bonus:
- `StatMod(effective relevant stat) + weapon.acc`.

Dodge bonus:
- `StatMod(effective AGI) + Status_GetSum(defender, "dodge_bonus")`.

Hit check:
- Forced miss if defender has `force_dodge` (consumes consume_on_defend statuses).
- Forced hit if attacker has `always_hit`.
- Else `d20 + acc_bonus >= d20 + dodge_bonus`.

Crit check:
- `crit_chance = 0.05 + max(0, StatMod(effective LUCK))*0.01 + crit_bonus*0.01`.
- Clamped to `[0.05, 0.50]`.

Base damage:
- `raw = weapon.power + StatMod(effective relevant stat)`.
- `mitig = floor(StatMod(effective DEF)/2)`.
- `base = max(1, raw - mitig)`.

Final damage order:
- Apply attacker status `dmg_mult`.
- Apply skill multiplier.
- Apply crit multiplier.
- Apply defender `guard_mult` (and consume consume_on_hit statuses if guard_mult field present).
- Apply difficulty side damage multiplier (attacker side).
- Clamp to `>= 0`.

Run check:
- Player run roll: `d20 + AGI mod`.
- Enemy run roll: `d20 + AGI mod`.
- Success if player roll `>=` enemy roll.


7. TURN FLOW / ACTION ECONOMY
Battle states:
- `MESSAGE`, `MENU`, `PLAYER_ATTACK`, `PLAYER_RUN`, `ENEMY_ACT`, `END_RUN`, `SKILL_MENU`, `ITEM_MENU`.

Message pacing:
- Message state auto-advances after `COMBAT_ACTION_DELAY` frames (default 60) and waits for FX completion.
- No player confirm-skip in this state.

Player turn:
- Actions: `FIGHT`, `SKILL`, `ITEM`, `RUN`.
- No-skill/no-item cases show message and return to menu.

Enemy turn:
- Action budget initialized per turn:
  - default 1 action
  - passive action-budget skills can raise it.
- Enemy chooses skill candidate based on:
  - trigger conditions (`hp ratio`, required inventory, etc.)
  - once-per-turn restrictions
  - per-skill random chance range.
- If no skill candidate selected, does basic attack.
- Free-action skills do not consume action budget.
- `set_enemy_actions` and `extra_turns` can extend chain.
- Chain cap is `ENEMY_ACTION_CHAIN_MAX` (default 6).

Win/loss/reward:
- Win: EXP with difficulty multiplier + loot roll, mark enemy defeated persist, fade back.
- Run: enemy persist restored alive, fade back.
- Loss: transitions to game-over cutscene path.


8. STATUS SYSTEM
Status DB entries are non-stackable; reapplying refreshes max(turns,power).
Exclusion rules are enforced on apply.

Status mechanics table:
- Poison:
  - stat mods: DEF -1
  - tick: HP -4..-2
  - excludes: Bleed
- Bleeding:
  - stat mods: AGI -1
  - tick: HP -4..-2
  - excludes: Poison, Burn
- Burning:
  - stat mods: DEF -1
  - tick: HP -5..-3
  - excludes: Bleed
- Stun:
  - stat mods: AGI -2
  - tick: none
  - flag: skip_turn
- Guard:
  - guard_mult: 0
  - consume_on_hit: true
- Rev Up:
  - dmg_mult: 2
  - consume_on_attack: true
- Evasion:
  - force_dodge: true
  - consume_on_defend: true
- Take Aim:
  - crit_bonus: +25
- Foresight:
  - always_hit: true
  - consume_on_attack: true
- Meditation:
  - tick: MP +2..+4
- Solidify:
  - force_dodge: true
  - consume_on_defend: true
- Bloodthirsty:
  - guard_mult: 0.5
  - dmg_mult: 1.08
  - consume_on_hit: true
- Blessing:
  - guard_mult: 0.7

Tick timing (actual):
- Player statuses tick at end of player action functions (including stunned skip branch).
- Enemy statuses tick at end of each `Battle_EnemyAct` call.
- Because enemy turns can chain multiple actions, enemy statuses may tick multiple times before player regains turn.

Status application direction:
- Skill target drives where status is applied (`self` vs `enemy`).
- Status icons are shared by both sides and rendered from status list of that character.

Status icons:
- Core debuffs use dedicated sprites:
  - `bleed_status`, `poison_status`, `stun_status`, `burn_status`.
- Player buff icons are assigned from last frame of corresponding FX sprites.

16. DISCREPANCIES / RISKS / HIDDEN BEHAVIORS
1) Level-up auto-growth mismatch (major):
- `LevelUp_Auto` chooses class stat but `LevelUp_AddStat` ignores `_stat_id`.
- Actual result: no automatic class stat gain, only +1 manual stat point each level.

2) Stat cap mismatch:
- `STAT_MAX`/`StatClamp` exist but manual stat allocation path does not clamp stats.
- Potentially unbounded stats from accumulated points.

3) DEF/INT retroactive resource scaling:
- HP/MP formulas use current DEF/INT mods multiplied by `(level-1)`.
- Spending DEF/INT points at high level can spike max HP/MP immediately.

4) Difficulty enemy stat double-scaling:
- Enemy stats multiplied in `EnemyCreate` and again in `Combat_EffectiveStat`.

5) Status tick pressure with multi-action enemies:
- Enemy statuses tick once per `Battle_EnemyAct` invocation, including chained actions.
- This changes duration/value relative to single-action turns.

6) Poison/Burn overlap:
- Poison and Burn can coexist (Bleed excludes both, but Poison and Burn do not exclude each other).
- Combined DOT + DEF debuff stacking can increase pressure.

7) Free-action buff spam risk:
- Blessing is free_action and not once-per-turn constrained; can chain if repeatedly selected.

8) Passive Fury visibility:
- Final boss Fury is passive action-budget logic (not an active cast); no explicit banner/log for trigger.

9) Skillbook chest + Nobody trap:
- Skillbook chest loot is class-based.
- Nobody class has no skillbook list; opening chest as Nobody can return empty and consume chest state.

10) Room transition anomalies:
- `rm_floor1` has an active room-transition instance (`inst_5DFCA07F`) with `transition_id = "floor9_5_to_ending"`.
- This creates an unexpected shortcut to ending cutscene from floor1.
- Additional orphan instance creation files exist (not referenced by room instance list), indicating stale room artifacts.

12) Confirm key hard-forced:

13) Equipment and resources:

14) Save/load enemy persist behavior:
