DEV NOTE - Tooltip Rework (Audit-First)

Date: 2026-03-01

Audit summary
- Existing tooltip builders/drawers were in scripts/scr_menu/scr_menu.gml:
  - Menu_BuildItemTooltipLines
  - Menu_BuildSkillTooltipLines
  - Menu_DrawTooltipBox
  - Menu_ItemFlavorText / Menu_SkillFlavorText
- Menu tooltip usage was in Menu_Draw() (inventory + skills tabs, bottom-right panel).
- Battle tooltip hook already existed in objects/obj_battle_controller/Draw_64.gml:
  - shown in BSTATE_SKILL_MENU and BSTATE_ITEM_MENU
  - previously called Menu_Build* and Menu_DrawTooltipBox.

What was reused
- Existing tooltip call sites in Menu_Draw and obj_battle_controller Draw event.
- Existing wrapping source Dialogue_WrapToLines for compact wrapping.
- Existing data fields from item/skill DBs (power/acc/stat_type/bonus/use.effect/status fields/passive_desc/class restrictions).

What was replaced
- Flavor-first text generation was removed from active usage.
- Replaced with mechanics-first shared tooltip module functions (implemented in scr_menu for now):
  - Tooltip_BuildItemLines
  - Tooltip_BuildSkillLines
  - Tooltip_DrawBox
  - Tooltip_ClampRect
  - Tooltip_GetStyle
- Added compat wrappers so older Menu_* tooltip calls remain safe.

Scalability changes
- Tooltip sizing/rendering is no longer scattered constants in Menu/Battle draw code.
- Both menu and battle now consume Tooltip_GetStyle("menu"|"battle").
- Added optional runtime override hook: global.tooltip_style
  - Supports per-context overrides (default/menu/battle) for:
    pad, text_scale, line_gap, frame_alpha_mult, min_w, min_h, margin_px, width_ratio, height_ratio.
- This enables future tuning without editing multiple draw call sites.

Battle hook update
- Battle selection tooltip now calls Tooltip_BuildItemLines / Tooltip_BuildSkillLines and Tooltip_DrawBox directly.
- Placement remains above the battle command box on the left, with GUI clamping via Tooltip_ClampRect.
