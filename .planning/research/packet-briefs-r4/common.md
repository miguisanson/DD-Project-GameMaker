# Common rules for every DD-Project packet (round 3 playtest fixes)

You implement ONE packet in your own git worktree (path given in your brief). Branch is already created off `next`.
Read `AGENTS.md` in your worktree (Rules 1-5, "The gate", "Traps") before editing. Design spec: `E:\Github_Projects\DD-Project-GameMaker\.planning\research\DECISIONS.md`.

1. **Check first.** Before changing game code, write the failing check: a new `Test_Suite_<Name>` appended at the END of `scripts/scr_test/scr_test.gml` (register it the way the last suites are registered), or a smoke/shots scenario in `scripts/scr_debug/scr_debug.gml` using ONLY the step range given in your brief. Run it and confirm it fails for the right reason (wrong value / not implemented). Expected values come from the brief, never copied from code output.
2. **Implement** until it passes. Stay inside the packet (Rule 3); list anything else you notice at the end of your report.
3. **Never** create/rename/delete a resource, never hand-edit `*.yy`, `DD-Project.yyp`, `DD-Project.resource_order`. `.gml` files are fine.
4. **Text:** player-facing strings go in `datafiles/localization/game_text.xlsx` (sheet `strings`, edit with openpyxl, keep en + ko), then `python tools/localization/build_localization.py --xlsx datafiles/localization/game_text.xlsx --json datafiles/localization/localization.json`, then run the lints the gate runs. Never hand-edit `localization.json`. Korean: write a sensible translation.
5. **Gate (run it yourself):** `powershell -NoProfile -ExecutionPolicy Bypass -File tools/automation/run_tests.ps1 -Mode fast -WorkRoot E:\Temp\dd-gate-<short>` from your worktree (use exactly the `<short>` in your brief; the path must contain "dd-gate"; never write `Temp*` folders into the repo). If your brief says so, also `-Only smoke` or `-Only shots` with the same WorkRoot; open the changed PNGs in `E:\Temp\dd-gate-<short>\shots` and look at them at every size. It must print GATE PASS.
6. Existing tests that assert the OLD behaviour you were asked to change: update them to the new behaviour and list every changed/removed assertion name in your report. Never weaken a test for anything else.
7. **Regression rows:** write `REGRESSION-ADD.md` in the worktree root (NOT committed: leave it untracked) with one row per fixed bug in the same column format as `.planning/REGRESSION.md` on branch v1.9, ids given in your brief.
8. **Commit** on your branch: first commit = the failing check(s) (`test(<short>): ...`), second = the implementation (`fix(<short>): ...` or `feat(<short>): ...`). End each message with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Do not merge, push, or touch other branches/worktrees.
9. **Report** (under 300 words): what changed (files, functions), the check names and that you saw them red then green, GATE PASS lines, changed/removed assertion names, anything left or noticed.
10. **Never kill processes by name** (no `taskkill /IM DD-Project.exe`, no `Stop-Process -Name`): the owner may be playing the game and other gate runs may be going. If your own run hangs, kill only the PID your run started (the gate prints/owns it), or let the gate's timeout end it.
